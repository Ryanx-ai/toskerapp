## Proposed Tosker interaction contract

1. Context and active Route are already visible. If no Route exists, offer a clear create-first-Route action; never silently write into another Route or context.
2. Search returns choices; selecting one opens a concise map preview. Manual placement does the same. One explicit **Add to [Route]** persists a Route Location and its Card. No first-result auto-save and no intermediate independent Pin write.
3. After success, the new Card and marker are selected. Pending/retry states retain the exact intended operation and target; stale context/Route changes cancel or require a fresh confirmation. Failed writes do not masquerade as saved destinations.
4. Selecting a Card reveals its marker and popup; selecting a marker reveals its Card. Selection/camera are local. Emphasize only incident route legs (previous→selected and selected→next), not all earlier legs. Preserve reduced-motion behavior.
5. Compact popup: name, short address, small icon/category control, Info, and relevant actions. Manual Rename only. On narrow/short viewports, anchor/clamp within safe map space; compact in-map fallback if necessary, not a routine screen-covering modal. Escape closes and restores focus; tab order and focus visibility survive pan/resize. Destructive Nuke keeps its existing confirmation.
6. The Location Card tray remains the only normal planning strip. Preserve reorder, position locks, comments, shared Skip, private Hide, Quick Order, automatic routing and existing recovery controls. Settings/custom icon art/new animation systems remain deferred.
7. Sandbox opens Map + Chat on desktop; mobile opens one primary surface. Sandbox Routes are owned by that Sandbox's user, not by a fake Personal Chat or a shared Room. No mutation to founder's retained Sandbox for testing.
8. Locate ON requests one current fix; OFF cancels pending work and clears it. Use the current user's avatar with a labelled fallback, plus a compact You/origin chip outside shared Route numbering. Denial/unavailable state is actionable and does not save a Checkpoint. Clear on context/access loss and unmount; no watch/history/background updates.
9. Default origin connector: local, dotted, unmeasured line to the first eligible stop. It is explicitly a connector, not a road route or ETA. Do not send current coordinates to the routing endpoint, persist them, broadcast them or include them in logs. A future optional private routed connector needs a separately reviewed privacy/quota path; it is not necessary to satisfy the dotted-connector option.
10. Summary overlay: Route name, eligible stop count, mode, and current provider travel distance/duration. Per-leg values appear only from validated matching provider data. During recalc/failure, keep saved places/order but suppress or clearly mark stale estimates. Order mode has no invented road metrics. Travel time is not live traffic or an arrival clock.

UX skill contribution: use the existing Tosker visual system, preserve context/selection continuity, make recovery explicit and ensure focus is not obscured. No replacement design system was generated. The plan above is a proposal pending the brief's execution-time gate, not implemented UI.

## Technical feasibility and cost boundaries

[MapLibre Popup API](https://maplibre.org/maplibre-gl-js/docs/API/classes/Popup/) and [options](https://maplibre.org/maplibre-gl-js/docs/API/type-aliases/PopupOptions/) support anchoring/offset, DOM content and focus behavior. Installed MapLibre is 6.11.2; its local `src/ui/popup.ts` also has padding constraints and `setPadding`. Reuse these capabilities with React-managed DOM and explicit teardown/focus restoration. Never interpolate user/provider text into unsafe HTML. Reject pointer-tracking/hover-only inspection for touch and keyboard users. Test safe-area collisions instead of assuming default anchoring is sufficient.

[Geoapify Routing documentation](https://apidocs.geoapify.com/docs/routing/) supplies total and per-leg distance/time, with default stopover waypoints mapping to legs/geometry. Preserve that mode; pass-through would change the mapping. Per-leg metrics can come from the existing response, without extra calls. Validate leg count, finite nonnegative values, units and point IDs before display. Traffic estimates are not live traffic. Current `route_details` adds cost; retain the existing two-credit-per-leg reservation for bounded Singapore routes, with no elevation, optimization, avoidance expansion or paid upgrade.

Local gap: `road-projection.ts` currently retains total estimates and road-name guidance but discards leg distance/time. `road-contract.ts` needs a provider-neutral leg DTO. `route-presentation.ts` currently emphasizes the prefix through the selected point, not just adjacent legs. Existing cancellation, request keys, private Hide/shared Skip, locks and one-shot geolocation are useful infrastructure to preserve, not rebuild.

## FP4B compatibility recommendation

Choose **dormant architecture / remove normal shelf**, not deletion or automatic migration. Keep `map_pins`, involvement/view state, provenance, authorization/revocation and independent Route Location relationships intact. Do not turn every Pin into a Route Card automatically. Existing memory can remain reachable through a compact secondary, explicitly labelled saved-memory entry; no second planning bar or automatic duplicate markers. Final entry placement is a checkpoint-A decision.

The retained Founder Review Pin is now `saved`, different from the old closeout's `want_to_go`; preserve the fresh state. Re-reading DB must precede any cutover. Hiding presentation does not revoke data rights. Source Nuke/member removal/Personal Chat suppression still apply even if memory is not in the normal view. Route deletion must not destroy dormant memory, and memory removal must not destroy copied Route Locations.

Sandbox Routes are a separate gap: `TripWorkspace` supplies an empty plan for Sandbox; `lockTripScope` supports Room/Subroom or accepted two-person Personal Chat only. The plan schema names its conversation owner `personal_conversation_id`. Do not simply accept any conversation ID or weaken Personal Chat checks. Audit an additive explicit Sandbox owner/context branch, constraints, unique scope, receipts, realtime invalidation, deletion/access boundaries and all API paths. Exact SQL is not yet designed or approved as a release artifact. Existing migration history must remain immutable; no destructive migration is proposed.
