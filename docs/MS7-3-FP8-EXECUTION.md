### Performance evidence and limitations

Browser-local phase marks contain phase/time only, not coordinates, query text, IDs or credentials. The real-origin test used an emulated public QA coordinate, never founder device location.

- Before optimization, deterministic shared-road/consent test waited 6,005 ms before private dispatch; response-to-render was 33 ms.
- Same idle-consent path after optimization waited 654 ms; response-to-render 26 ms. Removed ~5.35 seconds of unconditional waiting while retaining the remaining shared-request cooldown, private request cadence, explicit consent and server quotas.
- Real-origin run: Map initialization 1,176 ms (mock basemap); emulated geolocation 56 ms; user/test consent interaction 989 ms; dispatch wait 5,065 ms because the shared slot had just completed; full API request 8,369 ms, of which Geoapify 1,952 ms; response→fit 8 ms and response→render 17 ms. The ~6.4 s non-provider request overhead is not attributed solely to Geoapify or rendering. Existing authentication, repeated authorized database reads and network remain in that path; their boundaries were not removed to improve a benchmark.
- No continuous geolocation watcher, no persistent private-origin cache, no peer location consent inferred. Collaborative location-attached Pings remain private-only until a separately approved sharing-consent design exists.
