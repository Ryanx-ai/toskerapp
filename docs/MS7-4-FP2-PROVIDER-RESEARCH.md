# MS7.4 FP2 — provider research and cost model

12 October 2026. Save state **A**. Official public documentation reviewed today; USD estimates, not quotations or procurement approval. [Recovery](MS7-4-FP2-RECOVERY.md) distinguishes fresh account observations from historical receipts and documents the credential incident. ## Decision summary

Keep Ably, Geoapify, Vercel and Neon in place. No measured benefit presently justifies a migration. Evaluate **LiveKit Cloud voice-first** for future media because its managed service and self-hostable engine offer a useful exit path; **Daily** is a credible, potentially cheaper alternative for a small active cohort. This is an architectural recommendation, not a completed Singapore quality trial or permanent provider selection. No media account, billing method, paid resource or SDK integration was created.

Do not confuse Ably presence with voice. Browser WebRTC provides media primitives, not a complete secure group-call service. Six to eight active participants per initial Tosker room is a proposed product cap requiring enforcement, not a vendor-guaranteed limit. Registered-user count is not concurrency.

### Security, privacy and token lifecycle

Every media token must follow current Clerk session and exact Room/Subroom/Personal authorization, use a server-derived identity, admit only the chosen context and expose no provider signing secret. Token refresh rechecks membership; provider-side participant removal plus denied renewal is required for revocation. Short token expiry alone does not prove an already-connected participant has been removed. Keep the existing Ably exact-scope token boundary separate.

LiveKit tokens carry room/participant permissions; Cloud supports revocation behavior not identical to self-hosting. Reconnect token behavior requires deliberate tests. [Token grants](https://docs.livekit.io/frontends/reference/tokens-grants/). Optional [E2EE](https://docs.livekit.io/transport/encryption/) needs a client key-distribution and rotation design; encrypted transport alone is not a claim of end-to-end confidentiality. LiveKit's [October 2026 privacy policy](https://livekit.com/legal/privacy-policy) separates website policy from customer processor agreements; this research did not establish a universal media/metadata retention duration. Confirm DPA, subprocessors, region controls and diagnostic retention before provisioning.

Daily tokens should bind `room_name`, stable `user_id`, permissions and expiry. Explicitly consider `eject_at_token_exp`, which is not enabled by default; room privacy and participant ejection must be implemented, not assumed. [Meeting-token reference](https://docs.daily.co/reference/rest-api/meeting-tokens/create-meeting-token). Its pricing page distinguishes short metrics/log retention by account setup; that is not a complete customer-data deletion promise. Contractual metadata retention, regions and required browser versions remain gates.

Agora uses a server token service with channel/user/role scope and renewal callbacks; App Certificate stays server-only. [Token server](https://docs.agora.io/en/realtime-media/rtc/build/authenticate-users/deploy-token-server). Its published policy says RTC streams are not stored absent recording, while identifying operational data has separate retention periods, including 30 days for listed IP/channel/user identifiers and 365 days for device information, subject to applicable terms. [Agora privacy policy](https://www.agora.io/en/privacy-policy/). Do not enable recording, analytics extras or forced networking features by default.

Raw WebRTC/mediasoup shifts relay access control, IP exposure, logs, retention/deletion, patching and abuse protection to Tosker. A peer-to-peer path can expose network addresses to peers; TURN-only policies add cost and still require disclosure. No option removes the need for consent, visible capture indicators, immediate track shutdown on Leave/revocation and physical-device privacy tests.

### Evaluation before selecting media

Use isolated consenting QA participants, synthetic Room content and a founder-approved hard budget. Test two, four and six-to-eight speakers over Singapore Wi-Fi and cellular, plus JB if available: time to audible media, interruption recovery, jitter/loss, echo, Bluetooth/headphone changes, permission denial, background/lock-screen behavior and simultaneous Chat/Map responsiveness. Test current desktop browsers and physical iOS Safari/Android Chrome; viewport emulation cannot certify microphone/audio-session behavior. Start voice-only, no recording/transcription/video. Compare perceived intelligibility and measured failure rates before choosing on quality. Confirm current supported browser versions and account concurrency directly during provisioning; no unsupported numerical quality score is claimed today.

## Monthly usage model

Assume 40% of registered users use Live, each for four 30-minute sessions per month: **48 participant-minutes per registered user**. Each attendee contributes minutes; a four-person 30-minute call is 120 participant-minutes. Peak 10% concurrency is an illustrative capacity envelope, not derived from the monthly average.

| Registered users | Monthly participant-minutes | Illustrative peak concurrent participants |
| --- | ---: | ---: |
| 20–50 | 960–2,400 | 2–5 |
| 200 | 9,600 | 20 |
| 1,000 | 48,000 | 100 |

Model received audio at an aggregate 128kbps per participant (0.00096GB/minute), or received video at aggregate 1.5Mbps (0.01125GB/minute). Aggregate means all subscribed incoming tracks combined, not each track. These are planning assumptions, not measured SDK bitrates. At 48,000 minutes: approximately **46.1GB audio** or **540GB video**. Simulcast, room size, resolution, retransmission and subscription policy can change this substantially.

| Provider / illustrative plan choice | 20–50 users | 200 users | 1,000 users |
| --- | ---: | ---: | ---: |
| LiveKit voice | $0 Build | $50 Ship | $50 Ship |
| LiveKit video at model bitrate | $0 Build | $50 Ship | $84.80 Ship + transfer |
| Daily voice | $0 | $0 | $37.62 |
| Daily video | $0 | $0 | $152.00 |
| Agora voice, package model | $0 Free | $0 Free | $45.99 Starter |
| Agora HD video, package model | $0 Free | $45.99 Starter | $175.57 Pro + overage |
| Raw WebRTC / mediasoup | No license-minute quote; hosting, relay/egress, monitoring and engineering required | Same | Same; must load-test |

These are alternative all-audio or all-video scenarios, not costs to add together. No recording, AI, PSTN, support, tax, foreign exchange or custom network extras included. Plan choices illustrate publicly advertised options; purchase, top-ups and automatic overages are not authorized.

**LiveKit:** Build includes 5,000 WebRTC participant-minutes and 50GB downstream; Ship is $50/month with 150,000 minutes and 250GB, then $0.0005/minute and $0.12/GB. At the largest video scenario, 290GB overage adds $34.80. Doubling aggregate received video to 3Mbps makes that scenario approximately $149.60. Do not confuse WebRTC allowances with separate agent-minute allowances. [LiveKit pricing](https://livekit.com/pricing).

**Daily:** 10,000 free participant-minutes, then base audio-only $0.00099/minute or video $0.004/minute. A session that sends video can attract video pricing; voice savings require audio-only configuration. The largest case leaves 38,000 paid minutes. Free allowance exhaustion is not a guaranteed hard stop: implement budget admission/alerts before paid use. [Daily pricing](https://www.daily.co/pricing/video-sdk/).

**Agora:** Free includes 10,000 **standard** minutes with suspension; audio converts 1:1, HD video 1:4. Thus free HD allowance is 2,500 participant-minutes. Starter costs $45.99/50,000 standard minutes; Pro $133.99/150,000; extra standard minutes cost $0.99/1,000. Paid packages do not add another 10,000 free minutes. Largest HD model uses 192,000 standard minutes: $133.99 + $41.58. Top-up alternatives exist but are not assumed here. Actual aggregate resolution/subscriptions determine conversion. The $0.59 marketing rate is broadcast audience audio, not interactive voice. [Current RTC billing rules](https://docs.agora.io/en/realtime-media/rtc/reference/pricing). Automatic Cloud Proxy is advertised free; forced proxy configurations can introduce a $500 monthly minimum, outside this scope. [Agora pricing](https://www.agora.io/en/pricing/agora-rtc/).

Recommendation is **not** that LiveKit is cheapest: Daily's free allowance fits the modeled 200-user cohort while LiveKit requires Ship. Prefer LiveKit for the initial architecture/exit-path evaluation, subject to founder priorities and measured mobile quality. A bounded Free trial should use internal headroom below provider limits, for example at most 3,000 participant-minutes with transfer/concurrency caps, not exhaust the entire allowance during QA. Neither pricing research nor this proposed cap enables billing.

## Security incident, evidence gaps and gates

During the read-only Geoapify dashboard inspection, the project opened its key page and a generated example included a full key in browser-tool output despite masked key rows. A boolean-only local comparison identifies **server `GEOAPIFY_SEARCH_KEY`**; it is not the browser map key. No value is reproduced in these documents or committed. Treat the credential as exposed. The founder was informed during this turn.

Rotate through the secret-management workflow before implementation/provider QA, preserving restrictions, Free plan, environment separation and canonical continuity. Reconcile Development/Production assignments without printing values. An environment edit alone does not update an existing deployment; replacement verification, narrowly authorized rollout if needed and revocation must be coordinated. **No rotation, environment edit, revoke or deployment occurred.** This needs separate remediation authority/action under the current no-deploy gate.

Outstanding procurement facts: fresh Ably totals; actual Vercel/Neon billing and usage; media-provider account-specific quotas; Daily's exact current browser matrix; contracted retention/regions and SG mobile quality. These are explicitly unresolved, not grounds to invent values or demand credentials in chat. Research is complete with these bounded evidence gaps. They gate later provisioning/acceptance, not document completion.

No paid procurement, migration, added provider calls for geocoding/routing, media capture or new QA fixtures. No implementation, push or canonical change. FP1 stays live; FP2A awaits its 14–20-hour execution approval; FP2B provider selection remains pending.
